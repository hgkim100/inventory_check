# 매장 재고 자동 계산 도구

휴게소 매장의 종이 재고관리 대장을 자동화하는 단일 HTML 도구입니다.
손글씨로 채운 재고 대장과 키오스크 영수증을 폰으로 찍어 올리면, Gemini API가 OCR로 숫자를 읽어내고 브라우저에서 현재고와 소계를 계산해 보여줍니다.

> 사람이 최종적으로 종이 대장에 옮겨 적기 전에 한 번 더 검토하는 것을 전제로 만들어졌습니다. AI가 한 일과 코드가 한 일을 명확히 분리해, 어디서 어떤 숫자가 나왔는지 사용자가 검증할 수 있습니다.

---

## 어떤 문제를 푸나요

매장에서는 매일 마감 시 종이 대장에 다음을 손으로 계산해 적습니다.

```
현재고 = 전재고 + 입고 − 반품 − 판매
```

`판매`는 키오스크 영수증 1~3장의 같은 품목 수량을 합산해야 합니다.
품목이 수십 개라 매일 수십 번의 덧셈/뺄셈이 반복되고, 잘못 적으면 다음 날 전재고가 어긋납니다.

이 도구는 그 반복 계산을 자동화하면서도, **숫자를 어디서 가져왔는지 사람이 확인할 수 있게** 모든 식을 노출합니다.

---

## 사용 흐름

1. 폰에서 `inventory.html`을 엽니다. (GitHub Pages로 호스팅하거나 파일을 직접 열어도 됩니다.)
2. 첫 사용 시 우상단 ⚙️에서 **Gemini API 키**를 입력합니다.
   - 키는 [Google AI Studio](https://aistudio.google.com/app/apikey)에서 무료 발급 (분당 15회, 일일 1500회 한도).
   - 키는 브라우저 `localStorage`에만 저장됩니다. 외부 서버로 전송되지 않습니다.
3. **＋ 대장 사진 추가** — 손글씨 대장을 촬영하거나 갤러리에서 선택. 한 장에 다 안 들어가면 여러 장.
4. **＋ 영수증 사진 추가** — 키오스크 영수증을 1~3장 (순서대로 합산됩니다).
5. **분석하기** 버튼 → 10~40초 대기.
6. 카테고리별 카드 화면에서 검토:
   - ⚠️ 표시는 AI가 손글씨 인식에 확신이 없는 항목. 그 카드만 사진과 대조하면 됩니다.
   - 카드의 모든 숫자는 그 자리에서 인라인 편집 가능.
   - 누락된 항목은 카테고리 헤더의 **＋ 항목 추가**로 추가, 잘못 인식된 항목은 카드 우측 × 버튼으로 삭제.
   - 실수하면 **↺ 되돌리기**로 복구 (최대 50단계).
7. 검토가 끝난 현재고와 소계를 종이 대장에 옮겨 적습니다.

## 아키텍처 핵심 원칙

> **AI는 OCR만 한다. 계산은 JavaScript만 한다.**

이 분리가 신뢰성의 핵심입니다.

- Gemini에게 보내는 프롬프트에는 "계산은 절대 하지 마세요"를 명시.
- AI 응답은 raw 데이터뿐: `{ previous_stock, incoming, returns, sales_per_receipt: [12, 1, 0] }`.
- 모든 합산/계산은 순수 JS 함수(`calcItemSales`, `calcItemCurrent`, `calcGroupTotals`)가 처리.
- 카드 UI에는 계산식을 그대로 노출 (`294 + 600 − 13 − 0`), 영수증별 판매도 분리 표시 (`R1 + R2 + R3 = 13`).

이 원칙 덕분에 "AI가 덧셈을 틀리면 어쩌나" 하는 걱정 없이, 사용자는 OCR이 숫자를 제대로 읽었는지만 확인하면 됩니다.

## 주요 기능

- **사진 업로드** — 카메라/갤러리 양쪽 모두 사용 가능 (`capture` 강제 안 함).
- **이미지 자동 리사이즈** — Canvas로 대장은 max 2200px, 영수증은 max 1800px, JPEG 품질 0.85~0.88로 압축 후 전송 (API 트래픽/지연 최소화).
- **중복 사진 감지** — SHA-256(Web Crypto API)으로 바이트 단위 동일 파일 중복 첨부 방지.
- **카테고리별 그룹핑** — 대장의 "소계" 헤더를 기준으로 카테고리 분류 (꼬치전문점 / 떡볶이 / 주전부리 / 밥톡).
- **인라인 편집** — 모든 숫자는 클릭해서 바로 수정. 수정 즉시 합계 재계산.
- **항목 추가/삭제 + 되돌리기** — `focusin/focusout` 기반 스마트 스냅샷 (한 칸을 여러 번 수정해도 1단위로 묶임).
- **모바일 친화 입력** — `inputmode="numeric"`으로 숫자 키패드 자동 호출, 스피너 화살표 제거.
- **설정/API 키 관리** — localStorage 저장, "키 삭제" 버튼 제공.

---

## 기술 스택

- **HTML/CSS/JS 단일 파일** — 외부 의존성 0개. Tailwind/CDN/빌드 도구 없음.
- **Gemini API** (`gemini-2.5-flash` 기본, 설정에서 변경 가능)
  - 엔드포인트: `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`
  - `generationConfig.responseMimeType: 'application/json'`, `temperature: 0.1`
  - 이미지는 base64 인라인 첨부 (`inlineData.data`)
- **Web Crypto API** (`crypto.subtle`) — SHA-256 해시
- **Canvas API** — 이미지 리사이즈/압축
- **localStorage** — API 키, 모델명 저장

## 설치 / 배포

### 방법 A. 로컬 파일로 사용
```
git clone <repo>
inventory.html을 폰으로 전송 → 브라우저로 열기
```

### 방법 B. GitHub Pages
1. 이 저장소를 Fork 또는 그대로 사용.
2. Repository → Settings → Pages → Source: `main` branch, `/ (root)`.
3. `https://<user>.github.io/<repo>/inventory.html` 접속.

> iOS Safari에서 `crypto.subtle`은 HTTPS, `file://`, 또는 `localhost`에서만 동작합니다. 사파리 비공개 모드는 localStorage가 제한될 수 있습니다.

## 다른 매장에 적용하기

현재 4개 카테고리(꼬치전문점/떡볶이/주전부리/밥톡)와 그에 매핑되는 영수증 코드(`<0125>`, `<0181>`, `<0184>`, `<0197>`)가 하드코딩되어 있습니다. 다른 매장에서 사용하려면:

1. `CATEGORIES` 상수 — 매장의 카테고리 목록으로 교체.
2. `buildPrompt()` 함수 — 카테고리/영수증 코드 매핑 규칙 수정.
3. 필요시 손글씨 표기 관습(반품 기호 `△` `▽` 등)도 프롬프트에 추가.

## 알려진 한계

- **OCR 품질은 사진 품질에 좌우됩니다.** 형광등 정면 촬영을 권장합니다.
- **같은 영수증을 다시 촬영한 두 사진은 중복 감지 안 됩니다.** SHA-256은 바이트 동일성만 봅니다.
- **결과 저장/불러오기/내보내기 없음.** 한 세션에서 분석 → 종이 옮겨 적기로 완결됩니다.
- **카테고리 하드코딩.** 위 "다른 매장에 적용하기" 참조.
- **API 키 공유 위험.** 같은 폰을 다른 사람이 쓰면 키가 공유됩니다. "키 삭제" 버튼으로 해결.

## 개인정보 / 보안

- 사진과 API 키는 사용자 브라우저를 떠나지 않습니다 — 단 한 군데, **Gemini API 호출 시 Google로 전송**되는 것만 예외입니다 (그 외 어떤 서버로도 보내지 않습니다).
- 백엔드/분석 서버 없음. 정적 HTML.
- API 키는 사용자가 직접 발급하고 직접 관리합니다.

---

## 변경하면 안 되는 것

이 도구의 신뢰성을 떠받치는 결정들입니다.

- AI(OCR) ↔ JS(계산) 역할 분리
- 단일 HTML 파일 구조 (서버/빌드 도구 추가 금지)
- API 키 하드코딩 금지 (사용자가 자기 키 입력)

## 변경해도 되는 것

- UI 디테일 (색상, 레이아웃, 폰트)
- 프롬프트 표현 (역할 분리 원칙은 유지)
- 검증/편집 UX 개선
- 이미지 리사이즈 파라미터
- 카테고리 목록 (매장에 맞게)
